問1a　記憶装置のしくみ ア・イで2点

コンピュータの記憶装置は主記憶装置と補助記憶装置に大別される。一般に、主記憶装置に比べ、補助記憶装置はデータを読み書きする速度が ア であり、イ のために用いられる。

アの選択肢： 0低速　1同程度　2高速
イの選択肢： 0容量が小さく、データの短期的な保存　1容量が小さく、データの長期的な保存　2容量が大きく、データの短期的な保存　3容量が大きく、データの長期的な保存
用語チェック　主記憶装置はメモリのこと。CPUが直接読み書きする作業机で、速い代わりに電源を切ると中身が消える。補助記憶装置はSSDやHDDのこと。机の引き出しや倉庫にあたり、電源を切っても中身が残る。

考え方

  1. 2つの装置の「対比」を思い出す。主記憶装置＝速い・容量が小さい・短期保存。補助記憶装置＝遅い・容量が大きい・長期保存。この表が頭にあれば終わる問題。
  2. ア：速度は主記憶装置の方が速い。補助記憶装置は主記憶に比べて「低速」→ 0。
  3. イ：補助記憶装置の役割は「容量が大きく」かつ「長期的な保存」の2つがそろったもの。「容量が大きく・短期的」「容量が小さく・長期的」のような片方だけ合っている選択肢に引っかからないこと。
  4. 迷ったら具体例に置き換える。「SSDやHDD＝電源を切っても残る大きな置き場所」と考えれば、イは3しかない。
正解　ア ＝ 0（低速）　／　イ ＝ 3（容量が大きく、データの長期的な保存）
ここがポイント：主記憶と補助記憶は「速さ・容量・保存の長さ」の3点セットで対比して覚える。

問1b　情報セキュリティ ウ 2点

情報セキュリティに関する記述として最も適当なものを1つ選ぶ。

0犯罪につながる情報が公開されているWebサイトに日本国内からアクセスすると、不正アクセス禁止法違反になる。
1ネットワークの通信速度を高速にすることにより、マルウェアによる被害を最小限に抑えることができる。
2ソーシャルエンジニアリングによる被害を防ぐには、コンピュータの主記憶装置（メモリ）を増設することが有効である。
3保有するデータをバックアップしておくことで、情報セキュリティの要素である「可用性」を高めることができる。
4ファイアウォールを利用することによって、無線LANでの通信内容が盗聴されることを防ぐことができる。
用語チェック　情報セキュリティの3要素は、機密性（許可された人だけが見られる）、完全性（改ざんされていない）、可用性（必要なときに使える）。ソーシャルエンジニアリングは、電話やメールで人をだましてパスワードなどを聞き出す手口。ファイアウォールは、通信を許可するか遮断するかを判断する関所のような仕組み。

  1. 選択肢0：不正アクセス禁止法が禁じるのは、他人のIDを使うなどの「不正アクセス行為」。犯罪情報のサイトにアクセスするだけでは違反にならない → ×。
  2. 選択肢1：通信速度とマルウェア（ウイルスなどの悪意あるソフト）の被害は無関係 → ×。
  3. 選択肢2：ソーシャルエンジニアリングは「人をだます」手口なので、対策は利用者への教育や確認の手順。メモリ増設は無関係 → ×。

  5. 残った選択肢3：バックアップがあれば、障害やランサムウェアでデータが使えなくなっても復旧できる。つまり「必要なときに使える」＝可用性が高まる → これが正解。
正解　ウ ＝ 3
ここがポイント：「バックアップ＝可用性」「暗号化＝機密性」という対応で押さえる。対策と目的が対応しているかを1つずつ確かめるのが消去法のコツ。

問3　入力インタフェースと代表値 コ・サ 各2点

生年をホイール（リストをスクロールして中央に合わせる方式）で入力する。初期値は2000年。スクロールする移動距離を「スクロール距離」と呼ぶ。

コ：新規ユーザの生年の分布が過去の登録データと同じだとすると、スクロール距離の平均が一番小さくなる初期値は、候補（中央値1961／最頻値1967／範囲の中央の値1970／最大値2005）の中のどれか。

サ：誕生月も同じ方式で入力する。ただし月リストは循環する（12の下は1、1の上は12）。誕生月の分布に偏りがない場合、初期値をどの月にしてもスクロール距離の平均はどうなるか。

用語チェック　中央値は、データを大きさの順に並べたとき真ん中に来る値。最頻値は一番多く現れる値。代表値はデータ全体を代表させる値の総称（平均値・中央値・最頻値など）。

考え方（コ）

  1. まずスクロール距離の意味を確認する。初期値2000に対して、2008年生まれは8年分、1997年生まれは3年分スクロールする。つまりスクロール距離＝｜初期値 − その人の生年｜（絶対値の差）。
  2. 聞かれているのは「｜初期値 − 生年｜の平均を一番小さくする初期値」。ここで使える性質：絶対差の合計（平均）は、初期値を中央値にしたとき一番小さくなる。平均値が最小にするのは「差の二乗」の方なので、混同しないこと。
  3. 小さな例で確かめる。生年が {2, 3, 10} の3人だけだとする。初期値を平均値5にすると絶対差は 3＋2＋5＝10。中央値3にすると 1＋0＋7＝8 で、中央値の方が小さい。
  4. 分布のグラフの形を眺めても答えは出ない。「どの代表値が何を最小にするか」という性質で決まる問題。よってコは中央値（選択肢0）。

考え方（サ）

  1. 年の場合と決定的に違うのは、月リストが循環する（輪になっている）こと。端がない。
  2. 誕生月に偏りがない（一様）なら、初期値をどの月に置いても、各月までの距離の並びは「0, 1, 2, …, 11 の順番がずれたもの」になるだけで、合計も平均も変わらない。
  3. よってサは「どの月にしても変わらない」（選択肢3）。「真ん中の6月・7月にすれば近くなるはず」という考えは、端のある直線の場合の話で、輪には当てはまらない。
正解　コ ＝ 0（中央値）　／　サ ＝ 3（どの月にしても変わらない）
ここがポイント：「絶対差の平均を最小にするのは中央値、二乗の差の平均を最小にするのは平均値」。サは「月は循環する」という条件の読み取りが勝負。

問4a　メールアドレスの間違いはどこで検出されるか シ 1点・ス 2点・セ 2点

カオルさん（kaoru@example.ac.jp）がシノブさん（shinobu@example.ed.jp）にメールを送る。流れは「カオルさん → 送信側メールサーバA → 受信側メールサーバB → シノブさん」。次の宛先ミスのそれぞれについて、届けられないことが最初に検出されるサーバと理由の組合せを選ぶ。

あ： sinobu@example.ed.jp（ユーザ名の綴りミス）→ シ
い： example.ed.jp@sinobu（前後が入れ替わっている）→ ス
う： sinobu@exmple.ed.jp（ドメイン名の綴りミス）→ セ

選択肢は「サーバA／B」×「送信側のドメイン名が存在しない／受信側のドメイン名が存在しない／ユーザ名が存在しない／受信側のドメイン名とユーザ名の両方が存在しない」の組合せ。

考え方

  1. 大原則は2つだけ。ドメイン名が存在するかどうかは、宛先を調べる送信側サーバAの段階で分かる。ユーザ名が存在するかどうかは、受信側サーバBが自分の抱えるユーザと照合する段階で初めて分かる。
  2. あ：ドメイン example.ed.jp は実在するので、メールはBまで届く。Bがユーザ一覧を見て「sinobu というユーザはいない」と検出する → サーバB・ユーザ名が存在しない ＝ 5。
  3. い：メールアドレスは「ユーザ名@ドメイン名」の形。@の後ろがドメイン名だから、この宛先のドメインは「sinobu」という存在しないもの。Aが宛先ドメインを調べた時点で検出 → サーバA・受信側のドメイン名が存在しない ＝ 2。
  4. う：ドメイン exmple.ed.jp が存在しないので、やはりAの段階で検出 → サーバA・受信側のドメイン名が存在しない ＝ 2。ユーザ名も間違っているが、Bまで届かないので、ユーザ名の誤りは検出されない。「両方が存在しない」は選ばない。
誤りの例最初に検出するサーバ理由正解
あ sinobu@…Bユーザ名が存在しないシ＝5
い …@sinobuA受信側のドメイン名が存在しないス＝2
う sinobu@exmple…A受信側のドメイン名が存在しないセ＝2
正解　シ ＝ 5　／　ス ＝ 2　／　セ ＝ 2
ここがポイント：「ドメインの確認はA、ユーザの確認はB」。検出されるのは最初に引っかかる1か所だけ。また「送信側のドメイン名が存在しない」は、3例とも宛先（受信側）のミスなので当てはまらない。

目標時間：18分。Aは「誰が・何を・誰に送るか」を図の番号順に追う問題。Bは画素ごとのビット演算（OR／AND／NOT）の問題です。

A問1　紙の住民証明（図1）と電子データ（図2）の違い ア・イで3点（順序不問）

図1は、コンビニの多機能プリンタで住民証明（紙媒体）を印刷し、提出先へ持参・郵送する方式。図2は、請求者が自宅のPCから住民証明（電子データ）を請求して入手し、そのまま提出先へ送信できる方式。図2には図1と異なる特徴が2つある。

0デジタルデバイドが解消され、誰でも簡単に請求できる
1住民証明（電子データ）を入手するにはコンビニエンスストアを訪れる必要がある
2自宅や出先から住民証明（電子データ）を請求できる
3請求者が操作しなくても提出先は住民証明（電子データ）を入手できる
4入手した住民証明（電子データ）をインターネット経由で送ることができる
用語チェック　デジタルデバイドは、情報技術を使える人と使えない人の間に生じる格差のこと。

考え方

  1. 図1の不便さを先に確認する。請求者はプリンタのある場所まで出向き、印刷した紙を持参・郵送しなければならない。
  2. 図2の流れを番号順に追う。1 請求操作（自宅PCから）→ 2 データ要求 → 3 住民証明（電子データ）が役所からPCへ → 4 送信操作で提出先へ。消えた手間は「印刷のために出向く」ことと「紙を運ぶ」ことの2つ。
  3. 選択肢と照合する。2「自宅や出先から請求できる」＝出向く手間が消えた。4「インターネット経由で送ることができる」＝紙を運ぶ手間が消えた。この2つが図2の特徴そのもの。
  4. 落とす理由：0は逆で、PCとインターネット環境が前提になる方式なので格差はむしろ残る（広がりうる）。1は図1の説明。3は誤りで、請求も送信も請求者自身が操作する。
正解　ア ＝ 2　／　イ ＝ 4　（順序は問わない）
ここがポイント：設問の「図1と異なり」という一文が軸。2つの図で「請求者がどこで何をするか」の違いだけを見る。

A問2　アクセスコード方式（図3） ウ・エ・オで3点／カ 2点

図2の方式では、入手した住民証明（電子データ）を請求者が勝手に変更できてしまうおそれがある。そこで図3では「アクセスコード」方式にする。役所は請求ごとにアクセスコードを発行し、請求者はそのコードを提出先に渡す（4 送信操作）。提出先がコードを役所に示すと、対応する住民証明を受け取れる。図の5・6・7の段階に入るものが ウ・エ・オ。また、図2と異なり図3では カ 。

A問3　確認依頼コード方式（図4） キ 2点・ク 2点・ケ 3点

図3では、アクセスコードが第三者に漏れると住民情報が流出するおそれがある。そこで図4では「確認依頼コード」方式にする。住民情報そのものは、請求者が履歴書などに書いて提出先へ直接伝える。提出先は「確認依頼コードと住民情報」を役所へ送り、役所からは「正しいかどうか」の情報が返る。

図1〜図3で役所の役割は キ することだったが、図4では役所の役割を キ することから ク することに変更している。また、図4の確認依頼コードは図3のアクセスコードと異なり、ケ 。

キ・クの選択肢： 0住民情報を入手　1住民情報を提供　2住民情報を削除　3住民情報を電子化　4住民情報の誤りを訂正　5住民情報の正しさを証明
ケの選択肢： 0コードのコピーを誰も作れない　1コードだけを送信すれば住民情報を入手できる　2コードだけを送信しても住民情報を入手できない　3コードに住民情報が含まれる　4コードに住民情報が含まれない

考え方

  1. キ：図1〜図3を振り返ると、どの方式でも役所は「登録された住民情報を証明として相手に渡して」いた。つまり役割は「住民情報を提供する」→ キ＝1。
  2. ク：図4で役所が返すのは証明データではなく「正しいかどうか」の情報だけ。役所が担うのは情報の中身ではなく正しさの判定 → 役割は「住民情報の正しさを証明する」→ ク＝5。
  3. ケ：漏れたときの被害で対比する。図3のアクセスコードは、それ自体が証明を取り出す鍵なので、漏れれば第三者が住民情報を入手できてしまう。図4の確認依頼コードは照合に使うだけのものなので、コードだけでは何の情報も引き出せない → ケ＝2。

正解　キ ＝ 1（住民情報を提供）　／　ク ＝ 5（住民情報の正しさを証明）　／　ケ ＝ 2（コードだけを送信しても住民情報を入手できない）
ここがポイント：図4の発想の転換は「情報そのものは本人が伝える。役所は正しさの判定だけを担う」。だからコードが漏れても情報は漏れない。

B問1　マスク画像とのOR演算 コ・サ 各1点

画像は1画素を4ビットで表す16階調のグレースケールとし、黒＝0000、白＝1111 とする。キャラクターの部分をすべて白、透過したい部分をすべて黒にした画像（マスク画像）を用意し、背景画像と重ねて、重なる各点の4ビットについてビットごとにOR演算をする。

用語チェック　OR演算（論理和）は、2つのビットについて「どちらか一方でも1なら1、両方0のときだけ0」。ビットごとにとは、桁上がりをせず、同じ位置の桁どうしだけで計算すること。マスク画像は、残す部分と消す部分を白と黒で塗り分けた下準備の画像。

考え方

  1. 真理値表を書く。0 OR 0＝0、0 OR 1＝1、1 OR 0＝1、1 OR 1＝1。
  2. コは桁ごとに見る。
    桁1（左端）桁2桁3桁4
    マスク1111
    背景の点1010
    OR結果1111
    4桁すべてに少なくとも一方の1があるので、全桁1で 1111。
  3. サは 0000 と 0110。相手が0の桁では、もう一方の値がそのまま出る → 0110 のまま。
  4. 一般則として覚える：「1111とのORは必ず1111（白で潰れる）」「0000とのORは相手がそのまま」。この計算の意味は、キャラを置く場所は真っ白に潰れ、背景を残す場所は背景の値がそのまま残った画像ができること。
正解　コ ＝ 7（1111）　／　サ ＝ 3（0110）
ここがポイント：ORは2進数の足し算とは違う。桁ごとに独立で、桁上がりは一切ない。

B問2　合成を完成させる演算 シ 3点

B問1のOR演算で作った画像（キャラの場所が白く潰れ、背景の場所は背景の値のままの画像）に、キャラクター画像（キャラ＋白い背景）を重ねて、ビットごとに「ある演算」を行うと合成が完成する。「ある演算」は何か。

用語チェック　AND演算（論理積）は「両方1のときだけ1、それ以外は0」。NOT演算（否定）は0と1を反転させる。

考え方

  1. まず作戦の確認。合成は2段階だった。1段階目（B問1）で、背景画像にマスクをORして「キャラの場所だけ白く潰れた背景画像」を作った。2段階目（この問題）は、そこへキャラクター画像を重ねて、潰れた場所にキャラを埋め込む。
  2. 場所を2種類に分けて、「完成形では何が出てほしいか」を先に決める。値は具体例で見る。

    背景の場所背景の値（例 1010）白背景＝1111背景の値 1010
    キャラの場所1111（白く潰れている）キャラの値（例 0101）キャラの値 0101
    どちらの場所でも、「1111 と重なった側は消えて、もう片方の値がそのまま出る」ことが必要だと分かる。背景の場所ではキャラ画像側の白が消え、キャラの場所ではOR画像側の白が消える、という対称な要求である。
  3. ANDで実際に計算してみる。ANDは「両方1のときだけ1」だから、相手が全部1（1111）の桁では、自分の値がそのまま出る。

    キャラの場所桁1（左端）桁2桁3桁4
    ORで作った画像1111
    キャラクター画像0101
    AND結果0101
    キャラの値 0101 がそのまま出た。両方の場所で完成形どおりになる。
  4. 念のためORも試す。背景の場所で 1010 OR 1111 ＝ 1111。キャラ画像側の白背景が勝って、背景まで真っ白に潰れてしまう（B問1の「1111とのORは必ず1111」）。NOT付きの選択肢は、せっかく合った値が全部反転してしまう。だから残るのはANDだけ。

ここがポイント：ANDの合言葉は「1111とのANDは相手がそのまま」。白い部分は「相手を通す窓」になる。B問1のORが「白で塗りつぶす」演算だったのと、ちょうど対になっている。

B問3　ヒストグラムから背景の範囲を指定する ス 3点

背景が一色でない画像（図9：熊と、布のような一色でない背景）から、熊だけを切り抜くためのマスク（図10）を作りたい。色の範囲を指定して領域を選択できる画像編集ソフトで背景を選択する。図11は図9の各階調の画素数を表したヒストグラム（1画素8ビット、256階調。横軸は左が黒（暗い）・右が白（明るい））。背景（熊以外）だけを選択するには、階調のどの範囲を指定すればよいか。図11中の 0〜4 のうちから選ぶ。

用語チェック　ヒストグラムは、階調（明るさ）ごとに、その明るさの画素が何個あるかを数えたグラフ。明るさの分布が「山」として見える。

考え方

  1. まず図9を目で見て、明暗の対応を固定する。熊は中くらいの暗さ（グレー）、背景の布は全体に明るい。
  2. 図11を見ると山が2つある。左寄りの、なだらかで低い山が熊（暗めの階調に画素が散らばっている）。右寄りの、高くて鋭い山が背景（明るい階調に画素が集中している）。
  3. 図11の範囲の意味を確認する。0＝一番暗い端の、どちらの山にも入らない範囲。1＝熊の山の範囲。2＝背景の山の範囲。3＝熊の山の途中から背景の山まで。4＝熊の山の始まりから一番明るい端まで（ほぼ全部）。
  4. 「背景だけ」を選択したいので、背景の山全体を含み、熊の山を含まない範囲は2だけ。範囲を広く取りすぎると熊の一部まで含まれ、狭すぎると背景の一部が漏れる。「山全体を含み、2つの山の間の谷を越えない」ことが基準になる。
正解　ス ＝ 2
ここがポイント：ヒストグラムの2つの山を「どちらの部分の明るさか」と対応づけてから範囲を選ぶ。軸の向き（左＝黒、右＝白）の取り違えが一番のミス。

B問4　マスクを使った合成手順（図13） セ・ソで2点／タ 3点／チ 2点

風景画像（雪山）に、別の画像の熊の部分だけを切り抜いて合成する手順（図13）を考える。ここでは1画素8ビットで、黒＝00000000、白＝11111111 とする。手順は次の通り。

(1) 風景画像と セ をAND演算 → 熊の形に黒く抜けた風景画像ができる
(2) セ をNOT演算 → ソ
(3) ソ と熊の画像を タ 演算 → チ
(4) (1)の結果と チ をOR演算 → 合成が完成する

セ・ソ・チの選択肢は「背景と熊がそれぞれ何色か」を表した小さな画像（0〜5）。タの選択肢は 0 AND演算／1 OR演算／2 ANDの後にNOT／3 ORの後にNOT。

考え方

  1. 全体の作戦は「マスクを作る → NOTで反転したマスクも用意する → 風景側と熊側を別々に下ごしらえする → 最後にORで合わせる」。B問1・B問2の応用である。
  2. セを決める。(1)では風景画像とのANDで「熊を置く場所だけを黒（00000000）に抜き、他の場所は風景のまま」にしたい。ANDの性質「11111111とのANDは相手がそのまま、00000000とのANDは0になる」を使うので、セは「熊の部分が黒、背景が白」のマスク → セ＝3。
  3. ソは、セをNOT演算で反転させたもの。白と黒が入れ替わって「熊の部分が白、背景が黒」のマスク → ソ＝5。
  4. タとチを決める。熊の画像（熊＋明るい背景）とソを演算して、「熊だけが残り、背景は黒に潰れた画像」チを作りたい。背景の場所ではソが黒（00000000）なので、ANDなら熊の画像の背景部分が0に潰れる。熊の場所ではソが白（11111111）なので、ANDなら熊の絵がそのまま残る。よってタ＝AND演算（0）、チ＝「背景が黒、熊だけが残った画像」（0）。
  5. 最後の(4)：(1)の風景（熊の場所が黒＝0に抜けている）とチ（熊以外の場所が0）をORすると、0とのORは相手がそのままなので、抜けた場所にだけ熊の絵が入り、合成が完成する。
正解　セ ＝ 3（背景が白・熊が黒のマスク）　／　ソ ＝ 5（背景が黒・熊が白のマスク）　／　タ ＝ 0（AND演算）　／　チ ＝ 0（背景が黒・熊だけが残った画像）
ここがポイント：役割分担は「途中の振り分けはAND、仕上げはOR、反転はNOT」。各段階で「白＝残す側か、潰す側か」を必ず確認する。マスクの白黒が反対になると、熊ではなく背景の方が切り抜かれてしまう。

問4　回帰直線による開花推定日の補正 シ 3点・ス 2点

氷点下観測点について、2月1日以降に平均気温が氷点下だった日数（氷点下日数）と400度開花差の散布図と回帰直線（図3）を作った。回帰直線の方程式は、（開花差の予測値）＝ 0.55 ×（氷点下日数）＋ 5.48。

補正方法：開花差の予測値の小数第1位を四捨五入した値（補正日数）だけ、400度開花推定日からさかのぼった日を「400度補正日」とする。推定日よりも補正日の方が実際の開花日に近くなることを「うまく補正できる」とする。

シ：図3から分かること。　ス：別の年の観測点X（400度開花推定日は4月23日、氷点下日数は18日）の400度補正日。ス の選択肢は 0:4月5日／1:4月8日／2:4月12日／3:4月15日。

シの選択肢： 0すべての氷点下観測点でうまく補正できる　1散布図上にある点Aで示した氷点下観測点を除いたすべての氷点下観測点でうまく補正できる　2氷点下日数が1日である氷点下観測点の一部を除いたすべての氷点下観測点でうまく補正できる　3回帰直線上または回帰直線よりも上側に点がある氷点下観測点だけうまく補正できる　4回帰直線上または回帰直線よりも下側に点がある氷点下観測点だけうまく補正できる
用語チェック　回帰直線は、散布図の点の集まりの傾向を1本の直線で表したもの。x（ここでは氷点下日数）を代入すると、y（ここでは開花差）の予測値が得られる。あくまで「平均的な傾向」の予測で、個々の点は直線からずれる。

考え方（シ）

  1. 補正の発想を確認する。氷点下観測点では400度推定日が実際の開花日より遅れがち（開花差が正に大きい）。だから推定日から補正日数だけ「さかのぼって（早めて）」実際の開花日に寄せる。
  2. 条件を式にすると分かりやすい。実際の開花差を d、補正日数を c とすると、補正後の開花差は d − c。うまく補正できるのは |d − c| ＜ |d| のとき。d ＞ 0 の点では、これは 0 ＜ c ＜ 2d と同じ意味になる。
  3. c は回帰直線の上にある予測値なので、点が直線の付近にあれば c ≒ d でちょうどよく補正できる。直線より上に点がある観測点（実際の d が予測より大きい）では c ＜ d となり、必ず改善する。
  4. 困るのは、直線より下の点で d が小さい場合。c の方が大きすぎて行き過ぎ（補正後の絶対値が元の d 以上）になることがある。図3でこれが起きるのは、氷点下日数が1日の点の一部だけ（氷点下日数1日では c は約6日分になるのに、d が2や3しかない点がある）。
  5. 点A（氷点下日数が40日あまり、開花差が20の点）は直線より下にあるが、d＝20 に対して c は約29で、|20 − 29| ＝ 9 ＜ 20 と改善するので、Aも補正できる（「点Aを除く」という選択肢1は誤り）。よってシは選択肢2。

考え方（ス）

  1. 観測点Xの氷点下日数18日を回帰式に代入する。予測値 ＝ 0.55 × 18 ＋ 5.48 ＝ 9.9 ＋ 5.48 ＝ 15.38。
  2. 小数第1位を四捨五入して、補正日数 c ＝ 15（日分）。
  3. 補正日 ＝ 400度開花推定日（4月23日）から15日さかのぼる → 4月8日 → ス＝1。
  4. 検算：実際の開花日は4月12日。補正前はずれが |23 − 12| ＝ 11日、補正後は |8 − 12| ＝ 4日で、確かに近づいている（うまく補正できた）。
正解　シ ＝ 2　／　ス ＝ 1（4月8日）
ここがポイント：補正の向きは「さかのぼる（早める）」。「補正日数15日」と「補正日が15日」を混同しないこと（選択肢3の4月15日はその罠）。回帰直線は平均像なので、下側の点では補正が裏目に出ることがある、というのがシの読みどころ。
